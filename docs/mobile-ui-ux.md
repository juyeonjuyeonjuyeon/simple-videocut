# 개간단컷 모바일 UI·UX 기준

> 상태: 3단계 반응형 편집 화면·멀티터치·모바일 가져오기 적용
> 기준일: 2026-08-22

## 목표

iPhone에서는 한 손으로 빠르게 편집하고, iPad에서는 넓어진 화면을 활용하되 편집
영역을 여러 패널이 동시에 압박하지 않게 한다. 데스크톱 기능을 줄이는 것이 아니라
같은 기능을 기기 크기와 입력 방식에 맞는 위치와 순서로 제공한다.

## 현재 적용된 구조

### iPhone 세로

- 미디어 보관함은 왼쪽에서 잠시 열리는 패널로 표시한다.
- 선택한 요소의 속성은 타임라인 위에서 올라오는 하단 시트로 표시한다.
- 하단 시트는 축소·확대할 수 있고 닫기 버튼과 드래그 표시를 제공한다.
- 요소를 선택하면 재생 도구 옆에 `편집`을 표시하고, 추가 도구 대신 복제·삭제처럼
  현재 선택에 필요한 동작을 우선한다.
- 하단 타임라인에는 최소 210px을 확보하고 속성 시트가 타임라인을 가리지 않게 한다.

### iPhone 가로

- 낮은 화면에서도 미리보기를 숨기지 않는다.
- 타임라인 높이를 132px로 줄여 미리보기와 기본 재생 조작 공간을 확보한다.
- 속성은 화면 오른쪽의 작은 패널로 열어 미리보기와 타임라인을 동시에 확인할 수 있게 한다.

### iPad 세로와 Split View

- 미디어 보관함과 속성 패널은 한 번에 하나만 연다.
- 속성 패널은 편집 화면 위에 겹쳐 열고, 세로 화면에서는 미리보기 영역이 불필요하게
  세 열로 압축되지 않도록 안전 여백을 둔다.
- Split View처럼 폭이 좁아지면 iPhone과 같은 하단 시트로 자동 전환한다.

### iPad 가로와 Mac

- 충분한 너비와 높이가 있으면 기존의 좌우 고정 패널 구조를 유지한다.
- 좁은 창 또는 낮은 창에서는 기기 종류가 아니라 실제 사용 가능한 크기를 기준으로
  오버레이 패널 구조로 전환한다.

## 입력과 접근성 원칙

- 자주 누르는 아이콘과 탭의 터치 영역은 최소 44px을 유지한다.
- 아이콘 버튼에는 화면 읽기용 이름과 마우스 오버 설명을 제공한다.
- 현재 선택과 관계없는 기능은 좁은 화면에서 숨기고, 선택에 필요한 기능을 우선 노출한다.
- 미디어와 속성 패널을 동시에 열지 않으며 패널 바깥을 누르면 닫을 수 있게 한다.
- 화면 방향이 바뀌거나 Split View 폭이 변해도 현재 프로젝트와 선택 상태는 유지한다.
- 타임라인 항목은 VoiceOver와 키보드에서 버튼으로 인식하며 `Enter` 선택, `F2` 이름 변경,
  `Shift+F10` 편집 메뉴, `Delete` 삭제를 지원한다.
- 내보내기와 프로젝트 창은 대화상자 이름, 작업 중 상태, 진행 안내와 오류 알림을
  화면 읽기 프로그램에 전달한다.

## 터치 조작 적용 사항

- 타임라인의 일반 두 손가락 동작은 상하·좌우 스크롤로 유지하고, 핀치 또는
  `⌘/Ctrl + 스크롤`일 때만 확대·축소한다.
- 브라우저마다 다른 스크롤 값을 제한된 로그 배율로 변환해 한 번의 동작으로
  타임라인이 과도하게 확대되거나 축소되지 않게 한다.
- 미리보기의 모서리·변 조절점과 회전 손잡이는 보이는 크기와 별개로 44px 터치 영역을 제공한다.
- 모바일 회전 손잡이는 캔버스 밖에서 잘리지 않도록 선택 영역 안쪽에 표시한다.
- 모바일 재생 헤드의 드래그 영역은 52px로 넓힌다.
- 모바일의 `자르기`는 미리보기를 가리는 떠 있는 버튼 대신 선택 도구 막대에 표시하고,
  누르면 정밀 자르기 편집창을 바로 연다.
- 미리보기에서 선택한 영상·이미지·글자는 한 손가락으로 옮기고, 두 손가락으로
  이동·확대·축소·회전을 한 동작으로 조절한다.
- 두 번째 손가락이 닿거나 떨어질 때 현재 위치를 새 기준으로 삼아 요소가 갑자기
  튀지 않게 하고, 중앙 정렬과 45도 단위 회전에는 기존 스냅 규칙을 함께 적용한다.
- 모든 드래그는 시작한 손가락·Pencil의 포인터 ID만 따라간다. 다른 손가락이 화면에서
  떨어져도 재생 헤드, 트림, 크롭, 이동과 회전이 중간에 끊기지 않는다.
- 지원 기기에서는 중앙·각도 스냅과 길게 누르기 메뉴가 열릴 때 짧은 진동으로 확인한다.
- 재생 헤드 양옆의 편집 지점 버튼과 `↑`·`↓` 키로 컷, 각 레이어 시작·끝, 마커,
  위치 키프레임을 차례로 이동한다.

## 사진·영상·녹음 가져오기와 복원

- 미디어 보관함은 `모든 미디어 가져오기`와 함께 `사진·영상`, `녹음·오디오`를
  분리해 제공한다. iPhone과 iPad의 파일 선택 화면에서 원하는 종류를 찾기 쉽도록
  입력 형식을 구분하되, MOV·HEIC·M4A처럼 Apple 기기에서 흔한 형식도 유지한다.
- 사진 앱이나 파일 앱에서 복사할 수 있는 미디어는 편집 화면에 붙여 넣어 미디어
  보관함으로 가져올 수 있다. 텍스트 입력 중 붙여넣기는 가로채지 않는다.
- 파일 앱과 데스크톱에서는 기존처럼 화면 전체에 사진·영상·오디오를 끌어 놓을 수 있다.
- 자동 복원 회귀 검사는 모바일 WebKit 환경에서 영상, M4A 녹음, 사진을 함께 저장한 뒤
  페이지를 다시 열어 세 파일이 모두 복구되는지 확인한다. 영상과 녹음은 복원 뒤 MP4
  내보내기까지 이어서 검증한다.
- iOS 공유 시트에 이 앱을 직접 표시하는 기능은 별도의 iOS 앱 대상과 공유 확장이 필요하다.
  현재 저장소에는 네이티브 iOS 대상이 없으므로, 이번 단계에서는 파일 선택·끌어 놓기·
  붙여넣기를 안정적인 가져오기 경로로 제공한다.

## 캔버스 규격

- 빈 프로젝트뿐 아니라 요소가 들어간 편집 중에도 캔버스 비율과 픽셀 크기를 바꿀 수 있다.
- 기본 비율은 16:9, 9:16, 1:1, 4:3, 3:4, 4:5, 5:4, 21:9, 2:1을 제공한다.
- 사용자 크기는 너비 64~7680px, 높이 64~4320px 범위에서 정확히 입력하며 영상 코덱과
  호환되도록 홀수 입력은 가장 가까운 짝수 픽셀로 정리한다.
- 캔버스 규격은 미리보기, 플랫폼 모의 보기, 자동저장·프로젝트 파일, 내보내기가 같은
  값을 사용한다. 캔버스를 바꿔도 요소의 상대 위치와 크기는 유지한다.

## 자동 검증 기기 크기

다음 화면 크기를 반응형 회귀 검사의 기본값으로 사용한다.

| 상황 | 화면 크기 | 핵심 검증 |
| --- | ---: | --- |
| iPhone 세로 | 390×844 | 속성 하단 시트가 타임라인을 가리지 않음 |
| iPhone 가로 | 844×390 | 미리보기와 타임라인이 동시에 보임 |
| iPad 세로 | 1024×1366 | 한 패널 원칙과 미리보기 폭 유지 |
| iPad Split View | 744×1133 | 하단 시트 전환과 패널 겹침 방지 |

## 다음 모바일 상호작용 단계

1. 좁은 화면에서 재생 헤드를 고정하고 타임라인 자체를 움직이는 방식을 실제 기기로 비교 검토한다.
2. 네이티브 iOS 버전을 시작할 때 PhotosPicker·파일 선택기·음성 메모 공유 확장을 설계한다.
3. 브라우저가 노출하지 않는 Apple Pencil 이중 탭과 iOS 햅틱을 네이티브 입력에 연결한다.
4. 실제 iPhone과 iPad에서 VoiceOver, 화면 회전, 앱 전환 후 복원과 긴 프로젝트 내보내기를 검증한다.

새 모바일 기능은 위 기기 크기의 자동 검사와 실제 기기 검증을 모두 통과한 뒤 완료로 본다.
