# 개간단컷 모바일 UI·UX 기준

> 상태: 1단계 반응형 편집 화면 적용  
> 기준일: 2026-08-22

## 목표

iPhone에서는 한 손으로 빠르게 편집하고, iPad에서는 넓어진 화면을 활용하되 편집
영역을 여러 패널이 동시에 압박하지 않게 한다. 데스크톱 기능을 줄이는 것이 아니라
같은 기능을 기기 크기와 입력 방식에 맞는 위치와 순서로 제공한다.

## 현재 적용된 구조

### iPhone 세로

- 미디어 보관함은 왼쪽에서 잠시 열리는 패널로 표시한다.
- 선택한 요소의 속성은 타임라인 위에서 올라오는 하단 시트로 표시한다.
- 하단 시트는 축소·확대할 수 있고 닫기 버튼과 드래그 표시를 제공한다.
- 요소를 선택하면 재생 도구 옆에 `편집`을 표시하고, 추가 도구 대신 복제·삭제처럼
  현재 선택에 필요한 동작을 우선한다.
- 하단 타임라인에는 최소 210px을 확보하고 속성 시트가 타임라인을 가리지 않게 한다.

### iPhone 가로

- 낮은 화면에서도 미리보기를 숨기지 않는다.
- 타임라인 높이를 132px로 줄여 미리보기와 기본 재생 조작 공간을 확보한다.
- 속성은 화면 오른쪽의 작은 패널로 열어 미리보기와 타임라인을 동시에 확인할 수 있게 한다.

### iPad 세로와 Split View

- 미디어 보관함과 속성 패널은 한 번에 하나만 연다.
- 속성 패널은 편집 화면 위에 겹쳐 열고, 세로 화면에서는 미리보기 영역이 불필요하게
  세 열로 압축되지 않도록 안전 여백을 둔다.
- Split View처럼 폭이 좁아지면 iPhone과 같은 하단 시트로 자동 전환한다.

### iPad 가로와 Mac

- 충분한 너비와 높이가 있으면 기존의 좌우 고정 패널 구조를 유지한다.
- 좁은 창 또는 낮은 창에서는 기기 종류가 아니라 실제 사용 가능한 크기를 기준으로
  오버레이 패널 구조로 전환한다.

## 입력과 접근성 원칙

- 자주 누르는 아이콘과 탭의 터치 영역은 최소 44px을 유지한다.
- 아이콘 버튼에는 화면 읽기용 이름과 마우스 오버 설명을 제공한다.
- 현재 선택과 관계없는 기능은 좁은 화면에서 숨기고, 선택에 필요한 기능을 우선 노출한다.
- 미디어와 속성 패널을 동시에 열지 않으며 패널 바깥을 누르면 닫을 수 있게 한다.
- 화면 방향이 바뀌거나 Split View 폭이 변해도 현재 프로젝트와 선택 상태는 유지한다.

## 자동 검증 기기 크기

다음 화면 크기를 반응형 회귀 검사의 기본값으로 사용한다.

| 상황 | 화면 크기 | 핵심 검증 |
| --- | ---: | --- |
| iPhone 세로 | 390×844 | 속성 하단 시트가 타임라인을 가리지 않음 |
| iPhone 가로 | 844×390 | 미리보기와 타임라인이 동시에 보임 |
| iPad 세로 | 1024×1366 | 한 패널 원칙과 미리보기 폭 유지 |
| iPad Split View | 744×1133 | 하단 시트 전환과 패널 겹침 방지 |

## 다음 모바일 상호작용 단계

1. 타임라인 두 손가락 스크롤과 확대 제스처를 분리하고 확대 민감도를 조정한다.
2. 좁은 화면에서는 재생 헤드를 고정하고 타임라인 자체를 움직이는 방식을 검토한다.
3. 미리보기의 이동·크기 조절·회전 핸들을 손가락 입력에 맞게 확대하고 스냅 피드백을 보강한다.
4. 사진 앱, 파일 앱, 음성 메모 공유 시트와 드래그 앤 드롭 가져오기를 실제 기기에서 검증한다.
5. iPad 키보드·트랙패드 단축키와 Apple Pencil 선택 동작을 보강한다.
6. 실제 iPhone과 iPad에서 VoiceOver, 화면 회전, 앱 전환 후 복원과 긴 프로젝트 내보내기를 검증한다.

새 모바일 기능은 위 기기 크기의 자동 검사와 실제 기기 검증을 모두 통과한 뒤 완료로 본다.
